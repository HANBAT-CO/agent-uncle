# 사입삼춘 로컬 앱

기준 명세: 2026-10-10 「사입삼춘 — 앱 기획 및 사용자 워크플로」.

## 실행과 두 역할 확인

```sh
flutter pub get
flutter run -d chrome --web-port 5188 --dart-define=LOCAL_MODE=true
```

iOS 또는 Android는 `flutter run -d <device-id> --dart-define=LOCAL_MODE=true`로 실행한다. 기본 진입점은
`lib/main.dart`이며 `LOCAL_MODE=true`일 때 Supabase 초기화·인증·업무 API 호출 없이 실행된다.
사진이 없는 계정의 기본 아바타는 로컬 모드에서도 DiceBear API로 불러온다.
오프라인에서는 인물 아이콘을 표시하며 [프로필 이미지 안내](profile-images.md)를 참고한다.
기본 실행은 서버 모드이며 [서버 안내](supabase.md)를 참고한다.
빈 온보딩부터 시작하며 예시 거래나 계정을 자동 생성하지 않는다.

1. 로컬 계정을 만들고 소매업자로 가입한다. 사업자 서류는 테스트 파일로 첨부한다.
2. 내 정보에서 로그아웃한 다음 사입삼촌 계정을 새로 가입시킨다.
3. 거래처 탭에서 초대 코드를 복사한다. 소매업자로 다시 로그인하여 사입삼촌 탭에서 연결을 요청한다.
4. 사입삼촌으로 로그인하여 연결을 수락한다.
5. 소매업자가 요청을 보내고 사입삼촌이 수락·결과 공유·전달을 기록한다.
6. 소매업자가 회차별 수령을 확인한다. 남은 미송은 계속 처리할 수 있다.

로그아웃해도 기록은 유지된다. 브라우저 데이터는 origin/port별 IndexedDB에,
모바일 데이터는 앱 지원 디렉터리의 `saipsamchun-v1.db`에 저장된다. 서로 다른
기기·브라우저 저장소 사이의 연결과 원격 푸시는 제공하지 않는다.
로컬 계정 선택은 화면 개발을 위한 진입 방식이며 실제 사용자 인증이 아니다.

앱 UI는 TDS의 기존 컴포넌트를 조합하고, 홈·가입·업무 화면은 Figma 01–04의 배치를
따른다. 각 탭의 Navigator로 작성 화면과 스크롤을 유지하고, 탭 이동 전에 초안 저장을
완료한다. Paperlogy와 원본 Figma SVG는 유지하고, 기존 차콜·오프화이트 팔레트에
딥그린 강조색과 사용자 제공 검정 로고를 적용했다. 이미지는 TDS asset 컴포넌트로 표시하고,
카드·탭 컨테이너는 배치와 표면 장식만 담당한다.
컴포넌트 대응표와 테마 적용 범위는 [Figma 배치 안내](figma-layout.md)를 참고한다.
소매업자는 `홈 → 사입하기 → 채팅 → 사입삼촌 → 내 프로필` 순서이며,
사입삼촌은 `업무 → 채팅 → 홈 → 거래처 → 내 정보` 순서를 유지한다.
iOS 26+의 탭·알림 버튼은 [Apple Liquid Glass](liquid-glass.md)를 사용한다.

iPhone에서는 상세·채팅·설정 등 열린 페이지의 왼쪽 가장자리를 오른쪽으로 밀어
이전 페이지로 돌아갈 수 있다. Flutter 표준 iOS 라우트를 사용해 손가락 이동에 맞춰
전환하며, 짧게 밀었다가 놓으면 현재 페이지로 복귀한다. 각 탭의 첫 화면에서는
뒤로가기가 시작되지 않고, 상세에서 돌아오는 전환이 끝나면 기존 탭 선택 상태가 복원된다.
새 사입 요청은 초안 자동저장이 완료된 뒤 스와이프를 허용하며, 저장 중이거나 실패한
경우 입력을 보호한다. 가입 단계 이동은 기존 `이전` 버튼을 사용한다.

소매업자 홈의 `주문 넣기`는 사입하기 탭으로 이동한다. 이 탭은
`삼촌한테 사입하기` 버튼 하나로 주문 작성을 연다. 담당 삼촌·상품·사진·도매처·배송지를
한 폼에서 입력하며, 초안 저장과 기존 요청 수정·전송을 지원한다.
홈의 `사입 내역 전체 보기`와 현황별 `보기`는 별도 사입 내역 페이지를 연다.
확인 대기·진행 중·전달 대기·수령 확인·답변 필요·미송·완료를 필터링하고,
상품·도매처·사입삼촌 검색, 초안 복원, 다시 요청을 할 수 있다.
부분 확보·전달된 요청은 처리할 수량이 남은 각 단계에 함께 표시한다.

가입 단계는 하단 `다음` 또는 `가입 완료` 아래의 텍스트 버튼 `이전`으로 돌아간다.
첫 입력 단계에서 `이전`을 누르면 역할 선택으로, 역할 선택에서 다시 뒤로 가면
인증 세션을 종료하고 로그인 화면으로 돌아간다. 시스템 뒤로가기도 같은 순서를 따른다.
중단한 가입은 `complete: false`인 미완료 초안으로 남으며, 다시 로그인해도
필수 정보와 동의를 제출해 가입을 완료하기 전에는 업무 홈에 진입하지 않는다.
소매업자 배송지 단계는 주소·상세주소만 입력하고, 사입 시장은 선택 칩과
`그외` 직접 입력으로 저장한다. 입력값 저장은 유지하며 자동 저장 안내 문구는 표시하지 않는다.
두 역할의 첫 입력 단계에는 정산·환불용 은행명·계좌번호·예금주명을 필수로 입력한다.
계좌는 8~20자리 숫자를 받으며 공백·하이픈을 허용한다. 상대방의 검색·프로필에는 공개하지 않는다.
자동 저장에 실패하면 오류와 재시도 버튼을 현재 단계의 입력 영역 뒤에 표시한다.
오류 안내가 입력칸을 밀거나 키보드 포커스를 바꾸지 않도록 하며, 재시도 중에는
이전 오류를 유지하고 저장에 성공한 뒤에만 지운다.

## 데이터와 수량 처리

`SessionRepository`, `WorkspaceRepository`, `AttachmentRepository` 인터페이스는
Supabase 타입과 분리되어 있다. 기본 구현은 Sembast를 사용한다. 요청·회차·이력·
가입 단계·수령 확인·변경안·문제·메시지·알림을 개별 컬렉션으로 저장하며 작업 ID와 버전으로 재시도와
낡은 화면의 작업을 검증한다. 업무 기록·관련 메시지·알림은 하나의 트랜잭션이다.

- 수령 확인 ≤ 전달 ≤ 확보를 유지한다.
- 전달 가능 = 확보 − 전달 − 확보분 취소 − 확보분 보류이다.
- 미확보 취소분과 확보분 취소를 구분하여 이중 차감하지 않는다.
- 최종 이행 수량 = 요청 − 취소이다. 전량 수령과 문제·협의 해결 후 완료한다.
- 초과 수령은 실제 수량을 문제에 남기고 정정 전에는 확정 수량에 합산하지 않는다.
- 확보 수량 감소와 전달 정정은 제안·상대 확인을 거친다. 회차의 변경 전후와 사유를 보존한다.
- 프로필 주소 변경은 새 초안에 적용한다. 과거 요청과 전달 주소는 유지한다.
- 수령 확인 원기록은 별도 저장한다. 정정 시 새로운 확인 기록과 전후 이력을 추가한다.
- 전송 실패 메시지는 보낸 계정에만 표시하고 같은 메시지 ID로 다시 보낸다. 저장소 전체가 이용 불가하면 현재 입력 화면에서 내용을 유지한다.

첨부는 JPG/PNG, 사업자 서류는 PDF도 허용하며 파일당 최대 10MB이다. 파일 이름·
미리보기·교체·삭제를 제공하고 바이트는 기기에 저장한다. 서류 제출을 사업자 검증
완료로 표시하지 않는다. 사진·초안·요청·알림은 로그인한 계정의 관련 기록만 연다.
초대 코드는 기본 7일이며 재발급하면 이전 코드는 사용할 수 없다.

## 남겨 둔 외부 연결과 정책

Google·카카오 OAuth 구현은 `features/auth`에 보존하며 로그인 버튼 회귀 테스트도
유지한다. 로컬 모드에서는 호출하지 않는다. 기본 서버 모드는 Supabase 인증·권한·
데이터 검증·파일 저장·실시간 동기화를 사용하며 [서버 안내](supabase.md)에 정리했다.
사업자 서류의 실제 검증과 원격 푸시 연결은 별도로 필요하다.

가입 후 역할 변경은 제공하지 않는다. 가입 과정에서 필수 동의 항목과 약관 보기를 제공하며,
탈퇴 화면은 정책 안내까지만 제공하여 계정이나 거래 이력을 삭제하지 않는다.

## 검증

기기 통합 테스트와 촬영용 진입점은 일반 앱과 같은 앱 ID로 설치될 수 있다. 검증이
끝나면 해당 기기에 `lib/main.dart`를 다시 설치해 정상 실행본을 남긴다. 테스트용
`integration_test/…` 또는 `.context/…`를 시작 파일로 남겨 두면 앱 아이콘을 다시
눌렀을 때 자동 터치·스크롤이 재생되거나 촬영 신호 대기로 입력할 수 없는 화면이 뜬다.
Xcode의 생성된 `FLUTTER_TARGET`도 마지막 Flutter 실행의 시작 파일을 가리킬 수 있다.

```sh
# 검증을 끝낸 기기에 일반 서버 모드 앱을 복원한다. 앱 데이터는 삭제하지 않는다.
flutter run --no-pub --target lib/main.dart -d <device-id> --no-resident

# 로컬 모드로 사용하던 기기라면 LOCAL_MODE도 명시한다.
flutter run --no-pub --target lib/main.dart -d <device-id> \
  --dart-define=LOCAL_MODE=true --no-resident
```

일반 앱의 온보딩은 사용자가 `다음`·`시작하기`를 눌러야 진행한다. 시작 화면의
최소 3초 유지 이후에는 자동 탭 이동이나 자동 텍스트 입력을 실행하지 않는다.

```sh
flutter analyze
flutter test
(cd packages/tds_mobile_flutter && flutter test)
flutter build web
flutter build apk --debug
flutter build ios --simulator --no-codesign -d <ios-simulator-id>
flutter drive --driver=test_driver/local_app_driver.dart \
  --target=integration_test/local_app_test.dart -d <device-id>
```

업무 테스트는 명세 A/B/C, 부분 취소·보류·초과 수령·정정, 저장 실패 원자성,
중복 방지, 계정별 접근, 실제 저장소 재열기를 검증한다. 화면 테스트는 빈 설치에서
가입·재로그인, 정확한 5개 탭, 작성 중 탭 전환·스크롤 복원, 초안 복귀·전송, 저장 실패 재시도, 로그인 후 알림 목적지 및 수령 후 최신 내역을 검증한다. 기기 테스트는 양쪽 홈·
전달·텍스트 입력을 실행하며 `.context/saip-<platform>-*.png`에 캡처한다.
캡처 성공은 TDS 원본과의 픽셀 동등성을 뜻하지 않는다.

Android와 iOS의 통합 테스트는 테스트 전용 메모리 데이터를 만들며 기본 실행에 예시
계정이나 거래를 넣지 않는다. PDF는 이름·크기·등록 상태를 확인하며 이미지처럼 앱 안에서
문서를 렌더링하지 않는다. iOS 시스템 파일 선택기의 실제 파일 선택 동작은 자동화하지
않았다. 출시 서명·실기기 배포·서버 연결은 이번 검증 범위에 포함하지 않는다.

로그와 화면 캡처는 `.context/local-*.log`, `.context/saip-*.png`에 보관했다.
상세 화면별 대응표와 캡처 목록은 `.context/saip-verification.md`를 참고한다.
이후 Figma 배치 적용본은 앱 테스트 36개와 iOS/Android 통합 테스트를 통과했다.
최종 화면 검증 범위는 [Figma 배치 안내](figma-layout.md)에 기록했다.

현재 설치된 Flutter SDK에서는 대상 없는 `flutter build ios --simulator`가
universal engine의 아키텍처 검사에서 실패했다. `-d <ios-simulator-id>`로 실제
ARM 시뮬레이터를 지정하면 기본 앱 빌드가 통과한다. SDK나 TDS 패키지를 수정하지 않고
이 명령으로 검증했다.
