# 사입 동료와 팀 공동 업무

사입삼촌의 `연결` 탭에서 소매 거래처와 사입 동료를 구분하고, `대화` 탭에서
거래처 대화와 팀 동료 대화를 구분한다. 소매업자에게는 동료 추가나 내부 팀 대화를 노출하지 않는다.
기존 요청 상세에서 팀 픽업 업무로 이동하며, 홈에서 물류 상태와 청구·회수 상태를 따로 확인한다.

## 연결과 팀 권한

- 동료 연결은 상대 수락 후 성립한다. 동료 연결만으로 팀에 가입하거나 업무를 공유하지 않는다.
- 팀 생성, 동료 초대, 팀 참여 요청과 승인, 탈퇴를 제공한다. 한 삼촌은 하나의 활성 팀에 참여한다.
- 참여 요청은 팀장·운영자가 승인하며, 승인한 관리자가 아닌 요청자를 팀에 추가한다.
- 팀장과 운영자는 회차·구역·배정을 관리한다. 실제 포장 인수·인계·전달은 해당 담당자와 보관자가 처리한다.
- 팀원에게 필요한 도매처 위치, 수령 상호, 담당자, 요청 메모만 팀 업무에 복사한다.
- 수령 상호는 요청에 지정한 값을 우선하며, 없으면 요청의 상호 또는 등록 매장명을 사용한다. 개인 닉네임으로 대체하지 않는다.
  다른 거래처의 1:1 대화·계좌·전체 미수 장부는 공유하지 않는다.
- 팀에서 나가기 전 진행 중 배정·보관 물건·미확인 인계·미정산 책임을 정리해야 한다.
  계정 삭제로 남은 물건과 대납 책임을 자동 완료하지 않는다.

## 회차·구역·배정

`TeamWorkPage`에서 회차와 도매구역, 주담당·대체 담당, 근무 여부, 작업 한도와 마감을 설정한다.
`PickupRequestWorkPage`에서는 수락한 요청의 도매처별 업무와 실제 포장을 처리한다.
배정과 거래처 담당은 별개이며, 자동 배정은 실제 지급·픽업·청구·회수를 확정하지 않는다.
회차 생성과 업무 생성은 팀장·운영자만 처리한다. 업무에는 같은 팀의 활성 회차·구역과
팀원만 지정할 수 있고, 다른 팀의 구역 기록을 수정할 수 없다.

자동 배정은 위치와 구역·담당자가 명확한 미착수 업무만 처리한다. 위치 미확인, 구역 중복,
휴무, 작업량 초과, 마감 후 요청은 확인 사유를 남긴다. 이미 픽업한 포장의 보관자는 배정으로 옮기지 않는다.
같은 담당자로 배정을 다시 저장해도 픽업·인계·전달·수령 상태는 유지한다.

## 물건 인수와 인계

1. 픽업 담당자가 실제 받은 포장 식별자, 수량과 단위를 기록한다.
2. 현재 보관자가 받을 팀원과 포장을 선택하여 인계 요청을 보낸다. 이 단계에서는 보관자가 바뀌지 않는다.
3. 받는 팀원이 실제 받은 포장만 선택하여 확인한다. 부분 수령 시 나머지는 이전 보관자에게 남는다.
   인계 목록에는 보내는 팀원이 남긴 메모도 함께 표시한다.
4. 현재 보관자이면서 최종 전달 담당인 사람이 실제 전달한 포장만 전달 완료로 기록한다.
5. 소매업자는 본인에게 전달된 포장만 수령 확인한다. 상품 검수와 포장 수령은 별도다.

화면은 `내가 팀원에게 줄 물건`, `내가 받아야 할 인계`, `고객 전달`, `인계받기 전`을 구분한다.
포장 식별자·소매 상호·도매처·수량·단위를 함께 표시한다. 다른 단위의 수량을 합산하지 않으며,
총 포장 범위가 미확정이거나 미송이 남으면 전체 완료로 추정하지 않는다.
전체 수령 완료는 확정한 양수 포장 식별 수와 실제 포장 기록 수가 일치하고, 모든 포장이
수령 확인됐으며 미송·미해결 물건 차이가 없을 때만 표시한다. 범위 수정에는 최신 업무 버전을
요구하고, 이미 기록된 포장 수보다 작은 범위는 허용하지 않는다.

확인·전달·수령에는 포장별 버전을 요구한다. 인계의 `activeHandoffId`와 버전도 확인하여
오래된 카드나 중복 누름으로 같은 물건을 다시 옮기지 않는다.
현장 포장 기록은 실제 픽업 담당자만 생성하고 현재 보관자만 수정한다. 진행 중인 인계가 있거나
전달·수령이 끝난 포장은 현장 기록 수정으로 초기화할 수 없다.
삭제된 계정이 보관하던 미해결 포장은 팀장·운영자가 실제 인수 근거, 기존 보관자,
새 보관자와 버전을 제시한 `recoverPackageCustody`로 회수한다. 최종 전달 담당과 금전 기록은 유지한다.

## 대화와 업무 카드

소속 팀의 단체 업무방과 연결된 동료의 1:1 대화를 제공한다. 외부 동료에게는 소속 팀 업무방을 공개하지 않는다.
배정 결과·인계 요청·물건 차이·남은 업무 카드는 원본 업무 식별자를 참조하며,
카드에서 해당 배정·인계·포장 화면으로 이동한다. 여러 요청을 포함한 인계는 팀 전체 화면에서 처리한다.
카드를 읽거나 메시지를 처리하는 행동만으로 업무를 완료하지 않는다.

배정 카드는 구역·담당자·대상·배정 이유를 표시한다. 인계 카드는 방향·포장 식별자·수량·단위와
남은 물건을 표시한다. 실제 행동할 당사자에게 알림을 보내고, 공통 진행은 단체방 카드로 공유한다.

## 저장·재시도

입력은 계정별 `workflowInputs`에 보관한다. 전송 전 명령과 인자를 복사해 저장하고,
응답이 불확실하면 해당 입력을 잠근 상태에서 같은 operation ID와 내용으로만 재시도한다.
서버 확인 후 공동 상태를 반영한다. 명확히 거절된 입력은 수정할 수 있으며,
계정이 바뀐 뒤 이전 화면의 저장이나 전송을 새 계정으로 실행하지 않는다.
동기화 대기 화면에서도 미확정 명령을 확인하고 재시도할 수 있다.
기존 팀·회차·업무·인계 식별자로 새 기록을 만들 수 없다. 다른 식별자를 사용하더라도 같은
요청·도매처에 미완료 업무가 있으면 중복 생성을 거절한다. 이 보호는 로컬과 서버에 동일하게 적용한다.

## 데이터와 서버 연결

| 컬렉션 | 내용 |
| --- | --- |
| `colleagueConnections` | 삼촌 간 연결 요청과 수락 |
| `teams`, `teamInvites` | 팀 소속·역할, 초대와 참여 승인 |
| `teamChats` | 팀 단체방·동료 1:1 대화, 업무 카드 |
| `teamRounds`, `teamAreas` | 영업회차, 구역·근무·담당 규칙 |
| `teamJobs` | 도매처별 픽업 업무와 배정 |
| `teamPackages`, `teamHandoffs`, `teamReceipts` | 실제 보관·방향별 인계·수령 기록 |

로컬에서는 `team_commands.dart`, 서버에서는 `wf.*` 명령을 동일한 계약으로 처리한다.
팀 레코드는 `readers`와 서버 권한 검사를 적용하며, 소매업자에게는 본인 요청의 정제된
`pickupProgress`와 본인의 수령 확인 기록을 제공한다. 팀 내부 포장 원본은 공개하지 않는다.
팀원이 추가되거나 나가도 수령 확인자의 열람 권한은 유지한다.
공개 동료 디렉터리에는 연락처·사업자번호를 노출하지 않는다.
배포 순서와 추가 마이그레이션은 [서버 안내](supabase.md#픽업청구팀-업무-확장)를 따른다.
